# 2026-11-13

- Enforced shared-cache `s-maxage` precedence and `proxy-revalidate` semantics, and ensured `must-revalidate` blocks stale-while-revalidate and stale-if-error reuse. Added freshness unit coverage and threaded private/shared mode through freshness checks.
- Validate 304 response validators before merging cached metadata; preserve client conditional headers and retry unconditionally when a cache-generated validator receives a mismatched 304.
- Honor only-if-cached on cache-hit paths that require revalidation: return 504 without forwarding, stale-if-error fallback, or deleting the stored response.
- Invalidate all scoped URI variants after successful unsafe methods, including unknown-safety methods; preserve cached full responses across Range GETs and failed/safe requests.
- Do not store 206 responses without Range support and reuse cached HEAD responses after a matching 304.
- Treat request `max-age` as an age cap, measure `stale-if-error` from expiration, restrict fallback to eligible server errors and matching `Vary` requests, and preserve stored responses for request `no-store`.
- Accept all three RFC 9110 HTTP-date formats for `Date`, `Expires`, and date validators while rejecting obsolete non-GMT zone abbreviations.
- Accept lowercase spelling of the required GMT token while continuing to reject other timezone abbreviations.
- Preserve the stored representation's `Content-Length` on 304 merges and remove obsolete 1xx Warning values after successful validation.
- Send cached validators during stale-while-revalidate and coalesce concurrent background refreshes for the same cache variant.
